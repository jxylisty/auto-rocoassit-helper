## 3. build_hardened.py 六阶段流水线

```
[1/6] 密钥管理   build/_hardened/keys.json (首次自动生成 Ed25519 + data_seed)
                 └─ 公钥锚点自动写入 auth_core.py (公开信息, 可进 git)
[2/6] Cython     auth_core.py → auth_core.pyd (MSVC x64, vcvars64)
[3/6] 数据加密   src/pvp/data/{7个核心}.json → .bin 并删除明文
                 (pet_skills/pet_detail/pet_index/skills/skills_with_tags/pet_race_speed/leader_forms)
[4/6] 冒烟测试   子进程导入验证: pyd 可用 / seed 解密 / 重载链 / seed_cache 本机绑定
[5/6] PyInstaller 打包 (加密数据 + pyd 随包; 自动剔除开发机 auth.json)
[6/6] 产物检查   11 项 (pyd/密封 bin/无明文泄漏/无凭据泄漏/公开数据在位) → zip
```

### 参数
```powershell
D:\anaconda\python.exe tools\build_hardened.py              # 完整构建
D:\anaconda\python.exe tools\build_hardened.py --skip-seal  # 数据已加密过, 跳过第3步
D:\anaconda\python.exe tools\build_hardened.py --show-keys  # 查看 Worker 部署所需的三个值
D:\anaconda\python.exe tools\build_hardened.py --rotate     # 轮换密钥 (旧包数据作废!)
```

## 4. 开发环境说明（重要）

- **开发时代码仓库里数据是明文 .json**（loader 直读），一切照旧。
- **加密只发生在构建第 [3/6] 步**：`seal_assets.py` 把 .json 加密成 .bin 并**删除明文**——仓库会变成"只有 .bin"状态。
- **恢复开发明文**：`D:\anaconda\python.exe tools\seal_assets.py --seed <keys.json里的data_seed> --unseal`
- 或者保持 .bin 状态开发也能跑：本地 auth.json 里 `seed_cache` 恢复密钥后 loader 照常读 .bin。
- **git 注意**：`build/_hardened/keys.json` 绝不能提交！建议立即加 .gitignore：

```gitignore
build/_hardened/
```

## 5. Worker 部署/升级清单

1. 粘贴新版 `server/worker.js` 到 Cloudflare Worker → Edit code → Deploy
2. Settings → Variables and Secrets 增加两个 v2 变量：
   - `DATA_SEED` = keys.json 的 `data_seed`
   - `ED25519_PRIVATE_KEY` = keys.json 的 `ed25519_private_pkcs8`
3. 保存 → Deploy → 浏览器访问 `https://<worker地址>/healthz` 应返回 `{"ok":true,"ed25519":true,"seed":true}`
4. 老用户升级：新版客户端激活/联网校验时自动拿到 seed，数据解锁；无需人工干预

## 7. 已知残余风险（诚实清单）

1. **授权后的本机内存**：运行中 dump 内存可拿到解密后的数据/密钥。这需要动态分析能力，已从"改一个布尔值"升级到"逐版本提取"，且换版本（`--rotate`+重发）即失效。
2. **业务 pyc 仍可反编译**：bridge/battle_engine 等逻辑可见，但引擎启动被数据密钥门禁拦截——patch 门禁也读不了数据。若要进一步，可后续把 `pvp_pipeline/battle_engine` 也 Cython 化（build_hardened 第 2 步扩展即可）。
3. **seed_cache 本机可解**：攻击者在本机可从 auth.json 还原 seed（本机管理员权限本来就能做任何事）。该设计只防"整目录拷贝分享"。
4. **前端未混淆**：API 面暴露，但所有敏感动作都有服务端/门禁兜底。
5. **真·天花板**：客户端授权永远存在理论破解路径，目标是把成本抬到远超正版价格 + 破解版不稳定（轮换/更新即死）。
